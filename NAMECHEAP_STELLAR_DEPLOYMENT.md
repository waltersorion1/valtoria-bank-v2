# Deploy Valtoria Bank to Namecheap Stellar

This guide assumes the application will be installed at the root of its final domain, such as `https://example.com`, on a Namecheap Stellar shared-hosting account. Replace every placeholder before launch.

## 1. Complete the release gate first

1. Back up the project and local database separately.
2. Remove development customers and test transactions from the production database copy. Never upload the legacy SQL dumps in `sql/`; they contain inherited sample/personal data.
3. Confirm the legal, licensing, KYC/AML, privacy, card-data, credit, complaint, and retention requirements for every jurisdiction being served. HTTPS does not make manual storage of full payment-card details PCI compliant.
4. Keep email OTP disabled until working SMTP has been configured and tested.
5. Store the initial administrator password from `PRIVATE_ADMIN_CREDENTIALS.md` in a password manager. That file is deliberately excluded from Git and must not be uploaded.

## 2. Connect the domain

1. Sign in to Namecheap and open **Domain List → Manage → Nameservers**.
2. If Namecheap should manage hosting DNS, choose **Namecheap Web Hosting DNS**. For a domain held elsewhere, set:
   - `dns1.namecheaphosting.com`
   - `dns2.namecheaphosting.com`
3. If existing email or third-party DNS must remain in place, do not replace the nameservers. Instead, copy the Stellar server IP from the hosting welcome email and create the required `A` record for `@` and the appropriate `www` record at the current DNS provider.
4. Allow for DNS propagation. Nameserver changes can take up to 24–48 hours.
5. If this is not the hosting account's primary domain, open **cPanel → Domains**, add the domain, and record the document-root directory cPanel assigns to it.

Official references: [Shared Hosting getting started](https://www.namecheap.com/support/knowledgebase/article.aspx/177/27/shared-hosting-getting-started/) and [adding an addon domain](https://www.namecheap.com/support/knowledgebase/article.aspx/897/29/how-to-create-an-addon-domain/).

## 3. Select PHP and required extensions

1. Open **cPanel → Select PHP Version**.
2. Select PHP 8.2 or a later PHP 8.x release supported by the application.
3. Enable at least `pdo`, `pdo_mysql`, `mbstring`, `fileinfo`, `openssl`, `curl`, `json`, `session`, and `zip`.
4. Save the selection. Do not leave a public `phpinfo.php` file on the server.

Namecheap currently documents PHP selection under **Software** or **Exclusive for Namecheap Customers**. See [checking PHP configuration](https://www.namecheap.com/support/knowledgebase/article.aspx/9397/2219/how-to-check-php-version-and-configuration/) and [changing PHP/extensions](https://www.namecheap.com/support/knowledgebase/article.aspx/9417/2219/how-to-change-php-version-and-update-php-extensions-on-shared-servers/).

## 4. Create the production database

1. Open **cPanel → MySQL Databases** or **MySQL Database Wizard**.
2. Create a database, for example `cpaneluser_valtoria`.
3. Create a unique database user with a password generated by cPanel.
4. Add that user to the database and grant it **All Privileges**. Do not reuse the cPanel or administrator password.
5. Record the full prefixed database and username exactly as cPanel displays them.
6. Open **phpMyAdmin**, select the new database, and import a clean schema/data export from the tested local release. The export must include all migrations through `006_onboarding_controls.sql`, database triggers, and only production-approved data.
7. If deploying from the original base schema instead, import the sanitized base schema and apply migrations `001` through `006` in numeric order. Never reapply a migration that has already been incorporated into the imported database.
8. Confirm the tables exist and run the reconciliation checks from `DATABASE.md`; both must return zero discrepancies before opening the site.

## 5. Upload the application

1. Create a ZIP archive containing the project contents, including hidden `.htaccess`, `vendor/`, `assets/`, `admin/`, `app/`, `config/`, `database/`, `includes/`, `storage/`, `uploads/`, and the public PHP entry points.
2. Exclude `.git/`, `.env`, `PRIVATE_ADMIN_CREDENTIALS.md`, local screenshots/logs, tests, development seed data, and the `sql/` legacy dumps from the upload archive.
3. Open **cPanel → File Manager** and navigate to the domain's document root (`public_html` for the primary domain in the usual configuration).
4. Upload and extract the ZIP there. The result should be `public_html/index.php`, not `public_html/valtoria-bank/index.php`, unless the application is intentionally hosted in a subdirectory.
5. Ensure directories are normally `0755` and files `0644`. Never use `0777`.
6. Confirm `.htaccess` was uploaded by enabling **Settings → Show Hidden Files** in File Manager.

## 6. Create the production `.env`

Create `.env` beside `index.php`. Use plain values without surrounding quotes unless a value requires them:

```dotenv
APP_ENV=production
APP_DEBUG=false
APP_URL=https://YOUR-DOMAIN
APP_TIMEZONE=UTC
SESSION_NAME=valtoria_session
SESSION_IDLE_TIMEOUT=900

DB_HOST=localhost
DB_PORT=3306
DB_DATABASE=CPANEL_DATABASE_NAME
DB_USERNAME=CPANEL_DATABASE_USER
DB_PASSWORD=GENERATED_DATABASE_PASSWORD

MAIL_ENABLED=false
MAIL_HOST=
MAIL_PORT=587
MAIL_ENCRYPTION=tls
MAIL_USERNAME=
MAIL_PASSWORD=
MAIL_FROM_ADDRESS=no-reply@YOUR-DOMAIN
MAIL_FROM_NAME=Valtoria Bank
SUPPORT_EMAIL=support@YOUR-DOMAIN

FINANCIAL_PROVIDER_MODE=manual
SANDBOX_AUTO_COMPLETE=false
TRANSFER_STEP_UP_CENTS=0
```

The existing root `.htaccess` blocks dotfiles, but verify that requesting `https://YOUR-DOMAIN/.env` returns **403 or 404**, never the file contents.

## 7. Protect writable and sensitive storage

1. Verify `storage/uploads/.htaccess`, `storage/uploads/index.html`, `uploads/.htaccess`, and the upload placeholder files were included.
2. Keep PHP execution disabled in upload directories.
3. Prefer moving identity documents outside `public_html`; if that is not possible on the plan, keep them in the protected storage path and access them only through authenticated PHP delivery.
4. Make only the required storage directories writable by the hosting account. Start with `0755`; use `0775` only if Namecheap's PHP handler requires group write access.
5. Configure cPanel backups and download encrypted off-site copies regularly.

## 8. Create or update the super administrator

The included seeder is non-destructive and only creates or updates the specified administrator. It never resets the database.

If **cPanel → Terminal** or SSH is available, from the project document root run:

```bash
php database/seeds/super_admin.php --email='valtoriabank@gmail.com' --password='PASTE_FROM_PASSWORD_MANAGER' --name='Valtoria Super Administrator'
```

If Terminal/SSH is unavailable, generate a password hash locally with PHP's `password_hash()`, then use phpMyAdmin to create the user with `is_admin=1`, `role='super_admin'`, `status='approved'`, `kyc_status='verified'`, and `is_active=1`. Do not upload a web-accessible administrator creation script.

Afterward, sign in through `/login`, open the administrator dashboard, change the password, and verify the audit/settings pages. Remove the credential Markdown file after storing the replacement securely.

## 9. Install and enforce SSL

1. Point the domain to the Stellar account first. Certificate validation will fail while DNS points elsewhere.
2. Wait 30–60 minutes after the domain is connected. Stellar includes an automatically installed introductory PositiveSSL certificate for eligible domains.
3. Open **cPanel → Exclusive for Namecheap Customers → Namecheap SSL**.
4. Confirm the domain appears under the installed certificates and has a valid status. If a purchased certificate is under **Ready for installation**, choose it and complete the installation workflow.
5. Turn on **HTTPS by default** and **HTTPS Redirect** in the Namecheap SSL panel only after `https://YOUR-DOMAIN` loads successfully.
6. Test both `https://YOUR-DOMAIN` and `https://www.YOUR-DOMAIN` if `www` is in use. The browser must show a valid certificate with no mixed-content warning.
7. Test `http://YOUR-DOMAIN`; it must redirect once to the canonical HTTPS URL without a loop.
8. Do not add a second `.htaccess` HTTPS redirect when the Namecheap SSL redirect is already enabled. If the cPanel toggle is unavailable, use Namecheap's documented `.htaccess` method instead.
9. Monitor renewal in **Namecheap SSL**. The bundled certificate may have plan-specific promotional terms, so confirm renewal cost and automation well before expiry.

Official references: [Namecheap SSL on shared hosting](https://www.namecheap.com/support/knowledgebase/article.aspx/9387/2218/what-is-namecheap-ssl-and-how-do-i-use-it/), [manual cPanel certificate installation](https://www.namecheap.com/support/knowledgebase/article/9418/33/installing-an-ssl-certificate-on-your-server-using-cpanel/), and [HTTPS redirect using `.htaccess`](https://www.namecheap.com/support/knowledgebase/article.aspx/9770/38/how-to-use-htaccess-to-redirect-to-https-in-cpanel/).

## 10. Production verification

1. Confirm `/`, `/accounts`, `/login`, and `/register` load over HTTPS without `.php` in their public URLs.
2. Confirm `/admin/dashboard` redirects unauthenticated visitors to login and loads only for an authorized administrator.
3. Verify login, logout, password reset, registration, customer dashboard, mobile navigation, and admin navigation.
4. Confirm account creation follows the intended approval toggle and that email OTP remains disabled unless SMTP is functional.
5. Submit one low-risk test request through each manual workflow and verify pending → processing → completed/failed transitions and audit records.
6. Confirm no test users, fake balances, legacy SQL files, credential files, directory listings, debug errors, or PHP information pages are publicly accessible.
7. Check the PHP error log, application logs, database reconciliation, disk quota, backups, and SSL-expiry monitoring.
8. Only then switch the domain fully to production traffic.

## Rollback

Before deployment, retain the previous site archive and database backup. If verification fails, restore both the application files and their matching database backup together, disable registrations/operations if necessary, and investigate using server logs without enabling public debug output.
